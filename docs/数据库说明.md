# 数据库说明

## 1. 数据库概况

项目数据库名为 `smart_learning`，后端通过 MyBatis XML 映射文件访问 MySQL。当前代码中使用的业务表来自 `backend/src/main/resources/mapper/*.xml`，主要围绕专业、课程、知识点、职业和后台管理关系展开。

本文档只说明表结构和关系，不记录数据库账号、密码或本机隐私配置。

## 2. MyBatis 配置

`backend/src/main/resources/application.yml` 中配置了：

| 配置项 | 说明 |
| --- | --- |
| `server.port` | 后端端口，当前为 `8086` |
| `spring.datasource.url` | MySQL 连接地址，数据库名为 `smart_learning` |
| `mybatis.mapper-locations` | `classpath:mapper/*.xml` |
| `map-underscore-to-camel-case` | 开启下划线字段到 Java 驼峰字段自动映射 |

## 3. 核心数据表

### 3.1 `major` 专业表

| 字段 | Java 字段 | 说明 |
| --- | --- | --- |
| `id` | `id` | 专业 ID，字符串主键 |
| `name` | `name` | 专业名称 |
| `intro` | `intro` | 专业简介 |
| `created_at` | `createdAt` | 创建时间 |
| `updated_at` | `updatedAt` | 更新时间 |

作用：存储软件学院专业基础信息，供专业列表和专业详情页面展示。

### 3.2 `course` 课程表

| 字段 | Java 字段 | 说明 |
| --- | --- | --- |
| `id` | `id` | 课程 ID，字符串主键 |
| `name` | `name` | 课程名称 |
| `description` | `description` | 课程说明 |
| `created_at` | `createdAt` | 创建时间 |
| `updated_at` | `updatedAt` | 更新时间 |

作用：存储课程基础信息。课程类型和学分不放在课程表中，而是由 `major_course` 按专业关系维护。

### 3.3 `major_course` 专业课程关系表

| 字段 | Java 字段 | 说明 |
| --- | --- | --- |
| `id` | `id` | 关系 ID，自增主键 |
| `major_id` | `majorId` | 专业 ID |
| `course_id` | `courseId` | 课程 ID |
| `type` | `type` | 课程类型，例如专业必修、专业选修 |
| `credits` | `credits` | 学分 |
| `created_at` | `createdAt` | 创建时间 |
| `updated_at` | `updatedAt` | 更新时间 |

作用：建立专业与课程之间的多对多关系，并保存该课程在某个专业下的类型和学分。

### 3.4 `knowledge_point` 知识点表

| 字段 | Java 字段 | 说明 |
| --- | --- | --- |
| `id` | `id` | 知识点 ID，自增主键 |

## 4. 表关系说明

| 关系 | 说明 |
| --- | --- |
| `major` 1:N `major_course` | 一个专业可以关联多门课程 |
| `course` 1:N `major_course` | 一门课程可以被多个专业关联 |
| `course` 1:N `knowledge_point` | 一门课程可以包含多个知识点 |
| `career` 1:N `career_profile` | 当前业务约定一个职业只允许一条画像记录 |
| `career` 1:N `career_ability` | 一个职业可以有多个能力要求 |
| `career` 1:N `career_course` | 一个职业可以关联多门课程 |
| `course` 1:N `career_course` | 一门课程可以支撑多个职业方向 |
| `career` 1:N `career_knowledge_point` | 一个职业可以关联多个知识点 |
| `knowledge_point` 1:N `career_knowledge_point` | 一个知识点可以被多个职业引用 |

## 5. 主要查询 SQL 关系

| 功能 | SQL 关系 |
| --- | --- |
| 查询专业课程 | `major_course JOIN course` |
| 查询课程知识点 | `knowledge_point WHERE course_id = ?` |
| 查询职业相关课程 | `career_course JOIN course` |
| 课程反查职业 | `career_course JOIN career` |
| 查询职业知识点 | `career_knowledge_point JOIN knowledge_point JOIN course` |
| 后台关系列表 | 使用 `LEFT JOIN` 补充名称字段，便于页面展示 |

## 6. 数据维护约束

后端服务层已实现部分业务校验：

| 模块 | 约束 |
| --- | --- |
| 专业 | 专业 ID 不能为空且不能重复；已关联课程时不能删除 |
| 课程 | 课程 ID 和名称不能为空；课程名称不能重复；被关联时不能删除 |
| 专业课程 | 专业和课程必须存在；同一专业课程关系不能重复 |
| 知识点 | 所属课程必须存在；被职业知识点关系引用时不能删除 |
| 职业 | 职业 ID 和名称不能为空；被画像、能力、课程、知识点关系引用时不能删除 |
| 职业画像 | 职业必须存在；一个职业只允许一条画像 |
| 职业课程 | 职业和课程必须存在；同一职业课程关系不能重复 |
| 职业知识点 | 知识点必须属于所选课程；同一职业知识点关系不能重复 |
