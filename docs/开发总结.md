# 开发总结

## 1. 项目目标回顾

本项目目标是完成一个软件学院职业导航与学习推荐网站，通过前端页面、Spring Boot 后端接口和 MySQL 数据库，将专业、课程、知识点、职业方向和职业能力建立联系。

项目最终形成了两个主要使用场景：

| 使用场景 | 说明 |
| --- | --- |
| 学生浏览 | 从专业进入课程，再查看课程对应知识点和职业方向 |
| 管理员维护 | 在后台维护专业、课程、职业及多类关联关系 |

## 2. 开发过程总结

### 2.1 前端开发

前端使用 Vue 3 和 Vite 实现单页应用。页面路由集中配置在 `fronted/src/router/index.js`，普通展示页面和后台管理页面共用同一个前端工程。

主要工作包括：

| 工作 | 说明 |
| --- | --- |
| 展示页开发 | 完成首页、专业列表、专业详情、职业列表、职业详情 |
| 后台页开发 | 完成管理员登录、后台首页和 9 类管理页面 |
| 接口封装 | 使用 Axios 封装统一请求实例和后台接口方法 |
| 状态处理 | 对加载中、空数据、请求失败等情况做页面提示 |
| 数据兼容 | 对后端返回字段做一定兼容处理，避免空字段影响页面展示 |

### 2.2 后端开发

后端使用 Spring Boot + MyBatis + MySQL，实现了清晰的 Controller、Service、Mapper 分层。

主要工作包括：

| 工作 | 说明 |
| --- | --- |
| 项目搭建 | 完成 Spring Boot Maven 项目结构 |
| 数据访问 | 使用 MyBatis XML 编写多表查询 SQL |
| 公开接口 | 完成专业、课程、职业相关查询接口 |
| 后台接口 | 完成 9 类数据管理接口 |
| 统一响应 | 使用 `ApiResponse` 和 `Result` 返回 `code`、`message`、`data` |
| 登录拦截 | 使用拦截器保护后台接口 |
| 接口文档 | 集成 springdoc-openapi |

### 2.3 数据库开发

数据库设计围绕业务关系展开，重点不是单张表展示，而是表之间的关联：

| 关系 | 说明 |
| --- | --- |
| 专业和课程 | 通过 `major_course` 建立关联 |
| 课程和知识点 | 通过 `knowledge_point.course_id` 关联 |
| 职业和课程 | 通过 `career_course` 建立关联 |
| 职业和能力 | 通过 `career_ability` 关联 |
| 职业和知识点 | 通过 `career_knowledge_point` 建立关联 |

这样的结构能支撑前端从专业、课程、职业多个角度浏览学习内容。

## 3. 关键实现点

### 3.1 专业课程查询

课程基础信息保存在 `course` 表中，课程属于哪个专业、是必修还是选修、学分多少，则保存在 `major_course` 表中。因此专业课程查询通过：

```text
major_course JOIN course
```

这样可以避免在 `course` 表中重复保存专业相关信息。

### 3.2 职业课程查询

职业详情页需要展示“某个职业需要哪些课程”，后端通过：

```text
career_course JOIN course
```

返回课程名称、课程说明、课程作用、关联能力、重要程度和学习阶段。

### 3.3 职业知识点查询

职业知识点需要同时展示职业、课程和知识点信息，因此查询时通过：

```text
career_knowledge_point JOIN knowledge_point JOIN course
```

这样前端可以直接展示知识点名称、所属课程、应用场景和学习建议。

### 3.4 后台删除保护

后台删除操作没有直接删除所有关联数据，而是在 Service 层先检查引用关系。例如课程被专业课程、知识点、职业课程或职业知识点引用时，后端会返回错误提示，要求先删除关联记录。

这种做法可以减少误删数据造成的页面异常。

## 6. 当前不足

| 不足 | 说明 |
| --- | --- |
| 推荐算法较简单 | 当前主要依靠课程、职业、知识点关系展示推荐内容 |
| 权限控制较基础 | 当前后台只实现简单 token 拦截，没有角色权限细分 |
| 数据导入流程未自动化 | 数据库需要提前准备并导入业务数据 |
| 前台部分文案仍由页面组织 | 首页等展示内容主要在前端页面中维护 |
| 线上部署配置未完善 | 当前以本地运行和课程验收为主 |

## 8. 总结

本项目已经完成从前端页面到后端接口再到数据库关系的完整闭环。前台页面能够展示专业、课程、职业和知识点之间的关系，后台页面能够维护核心业务数据，后端接口结构清晰，数据库表关系明确，满足课程作业提交和项目答辩要求。
